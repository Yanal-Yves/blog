# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A French-language technical documentation site ("Notes Techniques") built with **Hugo** using the **hugo-book** theme. Statically generated, deployed to GitHub Pages at https://yanal.fargialla.com. All content is written in French.

## Commands

```bash
# First clone only — the theme is a git submodule and themes/ is empty without this
git submodule update --init --recursive

hugo server          # local dev server at http://localhost:1313/
hugo --minify        # production build into public/
```

A reproducible **Docker dev environment** is also available (pinned Hugo + Claude Code + Neovim) — see `CONTAINER.md`:

```bash
docker compose up dev        # Hugo live-reload at http://localhost:1313/
docker compose exec dev bash # shell inside the container (claude, nvim, gh, git)
```

There are no tests or linters. Deployment is automatic: pushing to `main` triggers `.github/workflows/deploy.yml`, which builds the site with Hugo extended (inside the pinned `blog-ci` image) and publishes `public/` to GitHub Pages with the `yanal.fargialla.com` CNAME. `public/` is committed but regenerated by CI — do not hand-edit it.

**Workflow: always through a pull request — never commit or push directly to `main`.** `main` is a protected branch: direct pushes are rejected server-side (`GH006: protected branch update failed`). Every change, however small, goes on a branch and reaches `main` via a PR. Merging the PR is what triggers the automatic deployment above.

### Pushing and pulling from the Docker dev container

The `origin` remote uses SSH (`git@github.com:…`). The dev container ships an `ssh` binary, so once an SSH **deploy key** is configured (set `DEPLOY_KEY` in `.env` — see `CONTAINER.md`), plain `git pull` / `git push` / `git fetch` work directly over `origin`, with no special handling.

If **no** deploy key is configured (`DEPLOY_KEY` unset → a neutral `/dev/null` key is mounted), git-over-SSH fails. Fall back to HTTPS using the `gh` token instead (this does not change the configured remote):

```bash
git -c credential.helper='!f() { echo "username=x-access-token"; echo "password=$GH_TOKEN"; }; f' \
  push https://github.com/Yanal-Yves/blog.git <branch>
```

Either way, the `gh` CLI and the GitHub API (creating PRs, `gh api`) always authenticate via `GH_TOKEN`, independently of the git transport — `gh auth status` should show the active account authenticated via `GH_TOKEN`.

## Content structure

Articles live in `content/<section>/`. Each section has an `_index.md` (with `bookCollapseSection: true` for collapsible nav) and ordered article files. Page ordering everywhere is controlled by the `weight` front matter field, not filename.

Front matter conventions used across the site:
- `title` — for numbered series, follows the `"SPF (Sender Policy Framework) - 4/9"` pattern
- `description` — set on every page; used for SEO meta tags
- `weight` — controls ordering in nav and article lists
- `enableGitInfo = true` in `hugo.toml` means the "last updated" date comes from git history automatically — do not add a `lastmod`/`date` field for that purpose

`unsafe = true` is set for the goldmark renderer in `hugo.toml`, so raw HTML in Markdown is allowed.

## Writing conventions

- **Never put a link inside bold text** (no `**[label](url)**`). The rendering is poor. Use a plain link `[label](url)`, or bold a separate word — but never both on the same text.

## Mermaid diagrams

- **Line breaks**: use `<br/>`, **never** `\n`. Hugo renders `\n` literally instead of interpreting it as a line break.
- **No numbered prefixes in node labels** (e.g. `"1. ..."`): Mermaid's Markdown parser treats them as ordered lists (`Unsupported markdown: list` error).

## Theme customizations (the non-obvious parts)

The global table of contents is **disabled** (`BookToC = false`). Custom pieces compensate:

- `layouts/shortcodes/toc.html` — a per-page inline ToC. Articles that want a ToC must explicitly include `{{< toc >}}` at the top. Styled by `.book-toc-inline` in `assets/_custom.scss`.
- `layouts/shortcodes/list-articles.html` — `{{< list-articles >}}` renders child pages ordered by weight; used in section `_index.md` files to build the article index.
- `layouts/partials/docs/inject/content-after.html` — injected at the bottom of **every** page: author byline, git-derived update date, the "AI-assisted, author-reviewed" notice, and the CC BY-SA 4.0 license.
- `layouts/partials/docs/inject/content-before.html` — renders the H1 page title.
- `layouts/partials/docs/inject/head.html` — Mermaid diagram styling (forces white background).
- `layouts/robots.txt` — custom robots.txt with sitemap directive (`enableRobotsTXT = true`).

`disableKinds = ["taxonomy", "term"]` — tags/categories pages are intentionally not generated.
